# n8n — планировщик пайплайна

n8n здесь отвечает только за **расписание** и **уведомление о падении**. Вся логика —
в Node-проекте (`src/`), ключи — в `.env`. Так пайплайн можно гонять и без n8n
(`npm run cycle full`), а n8n добавляет крон + историю запусков + ретраи.

## Вариант A — n8n через npx (тот же ПК)

```bash
# из папки проекта, в терминале где работает `node -v`
npm run n8n
```

Откроется http://localhost:5678. Дальше:

1. **Workflows → Import from File** → `n8n/gitsight-workflow.json`.
2. **Settings → Variables**: добавь `GITSIGHT_DIR` = `D:\claude\gitsight`
   (или задай переменную окружения `GITSIGHT_DIR` перед запуском n8n).
3. Открой workflow, нажми **Execute Workflow** на ноде «cycle full» — разовый прогон.
4. Убедись, что прошло, и переключи workflow в **Active** — заработает расписание
   (Пн/Ср/Пт 10:00 — цикл, ежедневно 12:00 — метрики; крон правится в нодах-триггерах).

## Вариант B — n8n в Docker

```bash
docker compose up -d        # см. docker-compose.yml в корне
```

Логин/пароль для UI берутся из `N8N_BASIC_AUTH_USER` / `N8N_BASIC_AUTH_PASSWORD`
в `.env`.

В этом варианте контейнер n8n **не видит** твой Node-проект. Варианты:
- прокинуть проект томом и поставить node в образ (сложнее), **или**
- держать n8n только для расписания, а `executeCommand` заменить на HTTP-ноду,
  которая дергает маленький локальный сервис-раннер (не входит в этот репозиторий).

Для одного ПК проще **Вариант A**.

## Что приходит в Telegram

Пайплайн сам (не n8n) шлёт альбом слайдов с кнопками «✅ Постить / ❌ Скип».
Нода n8n лишь сообщит, если процесс упал с ненулевым кодом (ветка «Цикл упал?»),
— повесь на неё Telegram/Email-ноду по вкусу.
